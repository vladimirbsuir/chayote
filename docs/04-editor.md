# 04 — Editor Specification

**Status:** Frozen. Last updated 2026-10-07.

---

## 1. Document format

**The ProseMirror JSON tree is the single source of truth.** HTML and plain text are derived. Markdown is not a storage format.

### 1.1 Root shape

Every note is a single `doc` node with block children. The tree is shallow by construction — there are no nested notes, no embeds, and no depth beyond what the schema allows.

```json
{
  "type": "doc",
  "content": [
    { "type": "heading", "attrs": { "level": 1 }, "content": [{ "type": "text", "text": "Meeting notes" }] },
    { "type": "paragraph", "content": [{ "type": "text", "text": "Discussed the " }, { "type": "text", "marks": [{ "type": "bold" }], "text": "launch date" }] },
    { "type": "taskList", "content": [
        { "type": "taskItem", "attrs": { "checked": false }, "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "Draft the announcement" }] }] }
    ] },
    { "type": "codeBlock", "attrs": { "language": null }, "content": [{ "type": "text", "text": "npm run tauri android dev" }] }
  ]
}
```

### 1.2 Schema

Node and mark names are fixed. Anything not listed here is not in v1.

| Node | Attributes | Content |
|------|-----------|---------|
| `doc` | — | `block+` |
| `paragraph` | — | `inline*` |
| `heading` | `level: 1\|2\|3` | `inline*` |
| `blockquote` | — | `block+` |
| `codeBlock` | `language: string \| null` | `text*` |
| `bulletList` | — | `listItem+` |
| `orderedList` | `start: integer` | `listItem+` |
| `listItem` | — | `block+` |
| `taskList` | — | `taskItem+` |
| `taskItem` | `checked: boolean` | `block+` |
| `horizontalRule` | — | empty |
| `hardBreak` | — | empty |

| Mark | Attributes |
|------|-----------|
| `bold` | — |
| `italic` | — |
| `strike` | — |
| `code` | — |

**No `link` mark in v1.** This is a deliberate omission. Links add a URL sanitisation surface (the `javascript:` scheme), a popover for editing, a security review, and Android share-intent ambiguity, in exchange for something a personal notes app can live without. Links arrive in v1.2 together with the attachment model, which resolves the sanitisation question properly.

**Heading levels cap at 3.** Deeper levels exist in HTML output only, generated by export, never authored in the editor.

### 1.3 Document invariants

Enforced at load, not only at save.

1. `doc` has at least one child. An empty document is normalised to a single empty `paragraph` before storage.
2. Total node count ≤ 50 000.
3. Nesting depth ≤ 12.
4. All node and mark `type` values are in the schema. Unknown types are dropped, not preserved.
5. Attribute values are coerced to the declared type; unknown attributes are dropped.
6. Text nodes are non-empty; adjacent text nodes with identical marks are merged.

A document violating any of these is rejected with `AppError::DOC_INVALID` and the *stored* version is kept. The user's unsaved buffer is offered for recovery — see §8.4.

## 2. TipTap configuration

```ts
import { Extension } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import Placeholder from '@tiptap/extension-placeholder'
import Typography from '@tiptap/extension-typography'
import TaskList from '@tiptap/extension-task-list'
import TaskItem from '@tiptap/extension-task-item'

const EditorShortcuts = Extension.create({ /* §7 bindings */ })

export const EDITOR_EXTENSIONS = [
  StarterKit.configure({
    heading: { levels: [1, 2, 3] },
    codeBlock: { HTMLAttributes: { class: 'code-block' } },
    dropcursor: { color: 'var(--accent)', width: 2 },
    gapcursor: false,
    link: false,
    trailingNode: false,
    undoRedo: { depth: 200, newGroupDelay: 500 },
  }),
  TaskList,
  TaskItem.configure({ nested: true }),
  Typography,
  EditorShortcuts,
  Placeholder.configure({
    placeholder: ({ node }) =>
      node.type.name === 'heading' ? 'Heading' : "Write something…",
    showOnlyWhenEditable: true,
    showOnlyCurrent: true,
  }),
]
```

Notes:

- `gapcursor: false` — a persistent gap cursor is visual noise in a minimal UI.
- `trailingNode: false` — prevents an always-present empty paragraph at the end, which would otherwise be picked up as the note title.
- `link: false` — StarterKit ships with a link module; it must be off in v1 (§1.2).
- `showOnlyCurrent: true` — the placeholder must not appear in every empty list item at once.
- `undoRedo` — TipTap 3 renamed the history extension; `depth` and
  `newGroupDelay` are the §6 values. `newGroupOnInputRule` is `true` by
  default in this version.
- **`EditorShortcuts`** is this project's own extension, carrying the
  editor-local bindings from `05-ui-ux.md` §7 that need editor commands rather
  than a raw view: the four marks, `Ctrl/Cmd+Enter` for a task item, and `Tab` /
  `Shift+Tab`. It must come **after** StarterKit, because TipTap merges every
  extension's shortcuts into one keymap and a later extension wins. That is why
  it re-implements the list half of `Tab` rather than inheriting StarterKit's
  `listKeymap`.

Clipboard out (§4.3) is not in this array. ProseMirror's
`clipboardTextSerializer` is a TipTap **core** extension, configured through the
editor options:

```ts
coreExtensionOptions: { clipboardTextSerializer: { blockSeparator: '\n\n' } },
```

### 2.1 EditorProps

```ts
const editorProps: EditorProps = {
  attributes: {
    class: 'note-editor',
    spellcheck: 'true',
    autocapitalize: 'sentences',
    role: 'textbox',
    'aria-multiline': 'true',
    'aria-label': 'Note content',
    'data-testid': 'note-editor',
  },
  handleDrop: (view, event) => {
    event.preventDefault()
    return true
  },
  handlePaste: (view, event) => {
    /* §4.1 rules 7 and 8, see below */
  },
  transformPastedHTML: (html) => sanitizeAndNormalize(html),
}
```

**There is no `transformPastedText`.** That hook is the obvious place for §4.1
rule 7 and it does not work there: ProseMirror treats its return value as *text*,
splits it on newlines, and wraps each piece in a paragraph. Returning
`<p>one<br>two</p>` therefore inserts those characters literally, and a single
newline is dropped rather than becoming a hard break. Rule 7 is implemented in
`handlePaste` instead, which builds a `Slice` with `hardBreak` nodes between the
lines and `paragraph` nodes between the blocks. `src/editor/pasteSanitizer.ts`
owns it.

`handlePaste` therefore has two jobs. For the HTML flavour it only decides
whether to insert at all, and defers the actual work to `transformPastedHTML`. For
the plain-text flavour it builds the slice itself and dispatches it. Rules 1–6 are
`transformPastedHTML`: DOMPurify strips everything outside the allowlist,
presentational attributes, and every `href`/`src`, then the DOM pass flattens
table cells and deep nesting.

Rule 8 is the part ProseMirror's parser cannot infer: a paste that yields nothing
must insert nothing and leave the selection untouched. Returning `true` consumes
the event; returning `false` hands it back.

`handleKeyDown` is **not** part of `editorProps`. The shortcuts in
`05-ui-ux.md` §7 need editor commands, and a keymap binding is the only place
that gets them; `EditorShortcuts` in `src/editor/extensions.ts` is that place.

`handleDrop` blocks every drop. v1 has no draggable block handles, so there is no
internal drag worth preserving, and `06-platform.md` §3.6 requires an external
file drop to change nothing: not insert content, not navigate the window away.

**The polarity matters and was wrong in an earlier revision of this sketch.**
Returning `false` from a ProseMirror `handleDrop` means *not handled*, which
hands the event to the browser default — the opposite of the intent stated in the
same paragraph. Blocking requires returning `true`, plus an explicit
`preventDefault()` so the drop never reaches the navigation handlers.

## 3. Input rules (Markdown shortcuts)

| Typed | Result |
|-------|--------|
| `# ` | heading level 1 |
| `## ` | heading level 2 |
| `### ` | heading level 3 |
| `- ` or `* ` | bullet list |
| `1. ` | ordered list |
| `1) ` | ordered list |
| `> ` | blockquote |
| ` ``` ` | code block |
| `--- ` or `*** ` | horizontal rule |
| `- [ ] ` / `- [x] ` | task list item, `checked` set accordingly |
| `**bold**`, `*italic*`, `~~strike~~`, `` `code` `` | corresponding marks |

Input rules fire at the start of a text block. A rule that would fire mid-word does not fire. Rules are provided by StarterKit and `@tiptap/extension-task-list`; nothing custom is required.

Smart typography runs on input and on paste:

| Input | Output |
|-------|--------|
| `--` | `—` (em dash) |
| `---` (surrounded by spaces) | `—` |
| `...` | `…` |
| `"` | `“` / `”` by position |
| `'` | `‘` / `’` by position |
| `(c)` | `©` |

Disabled inside `codeBlock` and inline `code`, which is handled by the extension.

## 4. Paste and clipboard

Paste is the single largest source of ugly content in a WYSIWYG editor. v1 treats it as a first-class concern.

### 4.1 Rules

1. HTML paste is sanitised through an **allowlist**. Only the node and mark types in §1.2 survive.
2. Presentational attributes (`style`, `class`, `width`, `align`, `bgcolor`, `id`) are stripped unconditionally. No exceptions for "known-safe" values.
3. Every `href` and `src` is rejected. v1 has no link mark and no image node, so there is nothing legitimate to keep.
4. `<script>`, `<style>`, `<iframe>`, `<object>`, `<embed>`, `<form>`, `<input>`, `<meta>`, `<link>` are removed with their subtree.
5. Nesting deeper than 12 levels is unwrapped.
6. Pasted block structure is preserved: lists stay lists, table cells are flattened to paragraphs in reading order.
7. Pasted plain text is split on blank lines into paragraphs; single newlines become `hardBreak`. This is built as a ProseMirror `Slice` in `handlePaste`, not in `transformPastedText` — see §2.1 for why.
8. A paste that yields an empty document inserts nothing and leaves the selection untouched.

### 4.2 Sanitiser

`DOMPurify` at paste time in the WebView, configured with an explicit tag allowlist matching §1.2 and `FORBID_TAGS` covering everything in §4.1 rule 4. Run it *before* ProseMirror parses the HTML, not after — sanitising the resulting ProseMirror tree means writing a second, easier-to-get-wrong traversal.

Two details that are not obvious and cost time to find:

- **Table elements are on the allowlist.** Rule 6 says table cells flatten to
  paragraphs *in reading order*, which needs cell order to survive sanitisation.
  So `<table>`, `<tr>`, `<td>` and friends pass through DOMPurify and are
  converted to `<p>` in a DOM pass afterwards, then unwrapped. Letting DOMPurify
  drop the table element leaves loose text nodes whose reading order is not
  guaranteed.
- **`ALLOWED_URI_REGEXP` is set to a pattern that matches nothing.** This is
  redundant while `ALLOWED_ATTR` omits `href` and `src`, and it stays that way on
  purpose: adding a URL attribute later cannot silently reopen a `javascript:`
  surface.

### 4.3 Clipboard out

Copy and cut use ProseMirror's `clipboardTextSerializer` extended to emit plain text with blank lines between blocks. This makes pasting into other apps produce readable output rather than one run-on line, and it is the clipboard behaviour users actually judge an editor by.

## 5. Autosave

Autosave is the most important behaviour in the app. A user who loses work will not try again.

### 5.1 Model

| Aspect | Decision |
|--------|----------|
| Trigger | `onUpdate`, debounced 800 ms |
| Debounce | `useDebounce` over the transaction, keyed on the document, not on a timer over the whole editor |
| Save unit | Whole document, `JSON.stringify(editor.getJSON())` |
| Flush conditions | note switch, selection change, editor blur, window blur, window close, app background on Android |
| Concurrency | One save in flight; a change arriving during a save schedules exactly one follow-up save |
| Comparison | Skip the IPC call if the serialised document equals the last-saved string |
| Error handling | Failure shows a persistent inline status, retries with backoff, keeps the buffer |
| Conflict | A note dirty locally *and* dirty in the incoming version is the user's call — see §5.4 |

Debouncing on the document rather than the transaction count means a continuous typing burst produces exactly one write, and an idle period produces none.

**Implementation shape.** `useAutosave` is a controller object, not a bag of
refs inside the component, and `EditorPane` passes the note to write as an
argument to every call. Two properties depend on that:

- A note switch flushes the *outgoing* note from inside `NoteEditor`'s unmount
  cleanup. React runs that cleanup before the replacement editor mounts, so the
  document being flushed is still the one on screen — but a cleanup cannot be
  awaited, so the target has to be captured rather than looked up.
- The serialisation comparison uses the document at the moment of the write, not
  the one captured at the keystroke. Anything else skips a real change.

The pending timer is dropped on unmount and on note switch, and there is never
more than one write in flight for a note.

### 5.2 Save indicator

Three states in the editor status bar: `Saved`, `Saving…`, `Unsaved changes`. No popups, no spinners over content, no confirmation dialogs. On failure it becomes `Couldn't save — retrying` in the accent-warning colour and persists until resolved.

### 5.3 Crash safety

The 800 ms debounce is the exposure window. On save completion the Rust side commits a WAL transaction with `synchronous = NORMAL` (`03-data-model.md` §2), which survives process termination. A hard power loss can lose at most the in-flight debounce window. There is no way to eliminate this without writing every keystroke, which is not acceptable.

### 5.4 Same-note external modification

Not reachable in v1 (single device, no sync). When the sync phase lands, the rule is: if the local note is dirty and the incoming revision is newer, do **not** overwrite. Park the incoming document and surface a non-modal choice — *Keep mine* / *Use the synced version* — with both versions recoverable. Never silently discard either.

## 6. Undo and redo

| Setting | Value |
|---------|-------|
| History depth | 200 |
| New group delay | 500 ms |
| New group on input rule | `true` |
| Undo shortcut | `Ctrl/Cmd+Z`, `Shift+Ctrl/Cmd+Z` for redo |

Undo history lives in the editor only and is never persisted. It is scoped to one note: switching notes and returning gives a fresh history. This is a known limitation and is acceptable — ProseMirror history across document loads requires serialising step history and is not worth the complexity.

Undo must not be able to reach into another note. When `note_id` changes, create a new editor instance rather than reusing the existing one; `editor.commands.setContent` does not clear history and will produce cross-note undo.

## 7. Title derivation

There is no title input in v1. `title` is derived from the document (`03-data-model.md` §4.1):

1. If the first block is a heading, its text is the title.
2. Otherwise the first non-empty block's text is the title.
3. Truncated to 120 characters on a word boundary.
4. Empty result displays as "Untitled".

The note list shows `Untitled` for such notes. The user gets a title by typing a heading, which is the behaviour Bear and Apple Notes have trained people to expect.

## 8. Validation, recovery, limits

### 8.1 Document size

| Limit | Value | Behaviour on exceed |
|--------|-------|---------------------|
| Serialised document | 5 MB | Reject the save, show `Note is too large`, keep the buffer |
| Node count | 50 000 | Reject on load (`DOC_INVALID`) |
| Nesting depth | 12 | Flatten on load |
| Plain text | 200 000 chars | Truncate the derived value, keep the document |

### 8.2 Validation

Structural validation happens in Rust at load (§1.3). The editor additionally trusts only its own schema.

### 8.3 Large documents

At 2 000 blocks the editor must remain responsive. Beyond that, the note is pathological for a personal notes app; no special handling is planned.

### 8.4 Recovery from a rejected document

If `notes_get` returns `DOC_INVALID`, the UI shows a recovery screen offering: the last saved version, and a read-only render of the rejected document so nothing is silently lost. This is a deliberate dead-end screen, not an editor.

## 9. Editor status bar

A single 28 px row at the bottom of the editor pane:

```
[left]                          [right]
Untitled · 342 words            Saved
```

| Element | Source |
|---------|--------|
| Title | Derived, `03-data-model.md` §4.1 |
| Word count | Derived at save |
| Save state | Frontend save state machine, §5.2 |
| Folder | Note's folder name, click to change |
| Tags | Note's tags, click to add or remove |

M2 ships title, word count, and save state. The folder and tag elements need M4's
data and arrive with it, rather than as controls that do nothing.

The save state carries the note it belongs to. A failure on a note the user has
already left must not paint the status bar of the note now open, so the store
holds both the state and its subject.

Nothing else. No cursor position, no selection statistics, no formatting hints. Those are editor-chrome features this app does not have.
